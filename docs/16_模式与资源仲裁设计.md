# 第16章 模式与资源仲裁设计

## 16.1 概述

模式与资源仲裁模块负责系统运行模式、设备运行模式、手动/自动模式、OWNER、资源锁和租约管理。它解决多个用户、任务、控制源和协同设备同时提出请求时“谁可以控制、控制哪些资源、何时释放”的问题。

模式允许操作，资源仲裁决定占用，安全联锁决定是否许可执行。三者是不同层次，任何一层不满足都不能下发运动命令。

## 16.2 设计目标

1. 支持全局系统状态与设备独立状态。
2. 支持 Manual/Auto 运行模式。
3. 允许 R1、R2、相机和 GAM1 独立运行或协同运行。
4. 通过 OWNER 和资源锁避免多控制源冲突。
5. 双臂协同必须原子申请全部资源。
6. 设备故障不自动拖垮无关设备和全局模式。
7. 模式切换有前置条件、过渡状态和审计。
8. OWNER 具有租约、续期、失效和强制释放机制。
9. STOP 和急停可以越过普通 OWNER 执行安全停止。
10. 仿真、真实和混合设备使用相同仲裁语义。

## 16.3 系统状态集

全局系统状态：

~~~text
OFFLINE
ONLINE
IDLE
RUNNING
FAULT
MAINTENANCE
DISABLED
SAFE_INIT
ESTOP_LATCHED
~~~

含义：

| 状态 | 说明 |
| --- | --- |
| OFFLINE | 进程未提供业务服务 |
| SAFE_INIT | 启动或复位检查阶段，默认禁止运动 |
| ONLINE | 服务在线但尚未进入可执行任务状态 |
| IDLE | 在线、无运行任务、允许在条件满足时接收任务 |
| RUNNING | 至少有一个任务或控制操作运行 |
| FAULT | 存在系统级故障，限制业务 |
| MAINTENANCE | 维护模式，普通自动任务禁止 |
| DISABLED | 管理员禁用，禁止控制 |
| ESTOP_LATCHED | 全局急停锁存，所有运动许可为 0 |

设备可以处于与全局不同的状态，例如系统 IDLE 而 R2 OFFLINE。

## 16.4 手动/自动模式

系统和设备分别拥有 mode：

~~~text
MANUAL
AUTO
~~~

### MANUAL

- 用户或维护人员直接控制；
- 普通自动任务不得抢占同一资源；
- 仍需权限、OWNER、Permit 和设备状态；
- JOG、MOVEJ 和 STOP 可用范围受设备策略限制；
- 断线、租约到期或模式退出时执行安全处理。

### AUTO

- 任务调度器可以申请资源；
- 手动控制默认被拒绝或进入等待；
- 允许配置高优先级人工 STOP；
- 自动任务受调度策略、时间表和安全联锁控制。

模式不是急停状态，切换模式不能清除急停锁存。

## 16.5 设备级模式

每个设备独立拥有：

~~~text
OFFLINE
INIT
IDLE
MANUAL
AUTO
RUNNING
FAULT
MAINTENANCE
DISABLED
STOPPING
~~~

设备模式切换只能影响本设备，除非该设备属于协同任务或共享安全资源。R1 进入 FAULT 时，R2 仍可以在自身资源、工作空间和 Safety Permit 允许时运行。

## 16.6 模式状态机

~~~mermaid
stateDiagram-v2
    [*] --> SAFE_INIT
    SAFE_INIT --> ONLINE: checks complete
    ONLINE --> IDLE: no active fault
    IDLE --> RUNNING: operation accepted
    RUNNING --> IDLE: all operations complete
    ONLINE --> MAINTENANCE: maintenance request
    IDLE --> MAINTENANCE: no conflicting operation
    MAINTENANCE --> ONLINE: leave maintenance
    IDLE --> FAULT: system fault
    RUNNING --> FAULT: critical fault
    FAULT --> ONLINE: fault cleared
    SAFE_INIT --> ESTOP_LATCHED: estop active
    ONLINE --> ESTOP_LATCHED: estop active
    RUNNING --> ESTOP_LATCHED: estop active
    ESTOP_LATCHED --> SAFE_INIT: reset sequence accepted
    ANY --> DISABLED: administrative disable
~~~

实际实现不得使用 ANY 作为隐式通配符，必须对每个来源状态建立明确转换白名单。

## 16.7 模式切换前置条件

### 16.7.1 切换到 AUTO

1. 用户拥有 system:mode 或 device:mode；
2. 当前不处于 ESTOP_LATCHED、DISABLED 或不可恢复 FAULT；
3. 相关设备连接状态满足策略；
4. 没有未释放的 MANUAL lease；
5. 运行中的手动命令已安全结束或停止；
6. 自动任务配置和资源声明通过校验；
7. Safety Permit=1；
8. 写入模式切换审计。

### 16.7.2 切换到 MANUAL

1. 用户拥有手动控制权限；
2. 自动任务已暂停、完成或按策略停止；
3. 自动任务释放同一资源；
4. Controller 处于可控状态；
5. 记录切换原因和操作人；
6. 如设备仍在运动，先执行受控 STOP。

### 16.7.3 进入 MAINTENANCE

1. 关闭自动调度；
2. 阻止普通控制；
3. 处理运行任务；
4. 释放普通资源；
5. 保留安全停止和诊断接口；
6. 记录维护窗口和操作者。

## 16.8 OWNER 模型

OWNER 表示当前控制主体，主体可以是用户、任务、维护会话或系统安全组件。

~~~text
Owner {
    owner_id
    owner_type: USER | TASK | MAINTENANCE | SAFETY | SYSTEM
    subject_id
    mode
    priority
    acquired_at
    expires_at
    renewable
    state
}
~~~

设备 PV/状态模型中可映射为：

~~~text
MRSS:ARM:R1:OWNER
MRSS:ARM:R2:OWNER
MRSS:VIS:HIK_FIX1:OWNER
MRSS:VIS:HIK_PTZ1:OWNER
MRSS:SNS:GAM1:OWNER
~~~

名称是状态接口约定，不代表一期需要 IOC。

## 16.9 资源模型

资源分为：

| 资源类型 | 示例 |
| --- | --- |
| DEVICE | ARM_R1、ARM_R2、HIK_FIX1、HIK_PTZ1、GAM1 |
| WORKSPACE | WORKSPACE_LEFT、WORKSPACE_RIGHT、WORKSPACE_SHARED |
| CHANNEL | PTZ_CONTROL、RADIATION_SAMPLE |
| SAFETY_GROUP | GLOBAL_MOTION |
| COMPOSITE | ARM_PAIR、ARM_CAMERA |

资源属性：

~~~text
Resource {
    resource_id
    type
    capacity
    exclusive
    parent_resource
    conflict_set[]
    state
}
~~~

一期大多数控制资源为独占资源，读状态和历史查询不需要资源锁。

## 16.10 资源锁和租约

Lease：

~~~text
Lease {
    lease_id
    owner_id
    resource_id
    acquired_at
    expires_at
    last_renewed_at
    state
}
~~~

租约必须有 TTL。服务端使用单调时间判断过期，同时使用系统时间写入审计。租约到期后：

1. 标记 EXPIRED；
2. 禁止普通新命令；
3. 触发设备安全停止或结束控制会话；
4. 释放资源；
5. 产生 OWNER_EXPIRED 告警；
6. 记录操作者和原因。

## 16.11 原子资源申请

~~~mermaid
sequenceDiagram
    participant S as service
    participant R as ResourceService
    participant DB as db
    participant C as Controller

    S->>R: acquire ARM_R1, ARM_R2, WORKSPACE_SHARED
    R->>DB: lock candidate resources
    alt all resources available
        R->>DB: create leases
        DB-->>R: commit
        R-->>S: lease set
        S->>C: submit coordinated plan
    else any resource busy
        R->>DB: rollback
        R-->>S: RESOURCE_BUSY
    end
~~~

不得先成功申请 ARM_R1，再以另一个调用申请 ARM_R2。所有冲突资源必须在同一仲裁操作中判断。

## 16.12 冲突规则

| 场景 | 资源结果 |
| --- | --- |
| R1 单臂 | ARM_R1 + LEFT |
| R2 单臂 | ARM_R2 + RIGHT |
| 双臂协同 | ARM_R1 + ARM_R2 + SHARED |
| 臂 + 固定相机 | ARM_x + HIK_FIX1 + 对应工作区 |
| 臂 + PTZ | ARM_x + HIK_PTZ1 + PTZ_CHANNEL |
| GAM1 采样 | GAM1 + SAMPLE_CHANNEL |
| 状态查询 | 无独占资源 |
| 全局急停 | SAFETY_GROUP，不等待普通锁 |

共享资源冲突集合由配置定义并在启动时校验无环。

## 16.13 优先级仲裁

资源请求比较：

1. 安全停止；
2. OWNER 类型 SAFETY；
3. CRITICAL；
4. HIGH；
5. MANUAL；
6. AUTO NORMAL；
7. 创建时间和 aging_score。

高优先级只能优先获得尚未被占用的资源，不能强制夺取正在执行且不可安全抢占的设备。强制停止必须经过安全策略并生成审计。

## 16.14 OWNER 续期

交互式 MANUAL 控制由客户端心跳续期：

~~~text
POST /api/owner/{owner_id}/renew
~~~

客户端失联、心跳超时、Token 撤销、用户退出或设备故障都会停止续期。续期失败不得被前端静默忽略，必须显示剩余租约和即将释放状态。

任务 OWNER 由 Scheduler 续期，任务结束、失败、取消或急停时释放。

## 16.15 强制释放

强制释放适用于：

- 租约过期；
- 用户被禁用；
- 任务取消；
- 设备离线；
- 系统进入维护；
- 全局急停；
- 管理员授权的故障恢复。

强制释放顺序：

~~~text
阻止新命令
  -> 请求安全停止
  -> 等待状态确认
  -> 标记 lease RELEASING
  -> 释放数据库锁
  -> 写审计
  -> 发布 RESOURCE_CHANGED
~~~

数据库锁释放失败时，启动恢复任务不能仅凭内存认为资源空闲。

## 16.16 查询与诊断

接口：

~~~text
GET /api/owner
GET /api/owner/{owner_id}
GET /api/resources
GET /api/resources/{resource_id}
POST /api/owner/acquire
POST /api/owner/{owner_id}/renew
POST /api/owner/{owner_id}/release
~~~

查询应返回 owner_type、subject、mode、lease expiry、resource、conflict 和状态。敏感用户信息按权限脱敏。

## 16.17 与任务调度的协作

- TaskRun 启动前申请资源；
- 资源获得后才提交 Controller；
- 任务运行期间续期；
- 点位完成不立即释放资源，直到任务策略允许；
- 任务暂停可保留或释放资源，必须显式配置；
- 任务取消必须释放资源；
- 任务异常和进程重启进入恢复仲裁；
- 协同任务所有资源使用同一 owner_id。

## 16.18 与安全联锁的协作

资源锁通过只代表“没有控制冲突”。最终许可：

~~~text
authorized
&& mode_allowed
&& owner_valid
&& resource_valid
&& device_ready
&& permit
&& !fault
&& !estop
~~~

安全 Permit=0 时，即使拥有 OWNER 也必须拒绝运动。急停触发时保留安全停止权限，但撤销普通控制许可。

## 16.19 故障隔离

资源仲裁故障分为：

| 故障 | 处理 |
| --- | --- |
| 单设备故障 | 释放该设备资源，其他资源继续 |
| 数据库锁超时 | 拒绝本次申请，告警 |
| 租约续期失败 | 进入 RELEASING，停止相关控制 |
| 仲裁服务不可用 | 禁止新运动，保留 STOP |
| 资源配置冲突 | 启动拒绝或进入维护 |
| 协同一方故障 | 触发协同停止和任务失败 |
| 全局急停 | 撤销所有普通 owner |

## 16.20 测试设计

1. 单设备、双设备和共享空间锁；
2. 双臂原子申请成功/失败；
3. OWNER 续期、过期和强制释放；
4. Manual/Auto 模式切换；
5. 同优先级公平和 aging；
6. 高优先级等待但不危险抢占；
7. 设备离线和数据库锁超时；
8. 用户撤销、任务取消和系统维护；
9. 急停撤销普通 owner；
10. 重启后租约恢复和清理；
11. 多线程并发 acquire 竞态；
12. 资源图配置环和冲突校验。

## 16.21 验收追踪

- 系统和设备模式可独立查询；
- Manual/Auto 语义清晰；
- OWNER、租约、资源锁有稳定模型；
- 双臂协同资源原子申请；
- 设备故障按实例隔离；
- Permit=0 和急停时任何普通 owner 都不能运动；
- STOP 不等待普通资源锁；
- 资源变更有审计和事件；
- 仿真、真实、混合模式仲裁一致。

## 16.22 本章小结

本章完成了系统模式、设备模式、Manual/Auto、OWNER、资源锁、租约、冲突、优先级、原子申请、强制释放和安全协作设计。模式决定运行语境，资源仲裁决定控制归属，安全联锁决定最终许可；三者互相协作但不能相互替代。
