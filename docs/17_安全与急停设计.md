# 第17章 安全与急停设计

## 17.1 概述

安全模块负责系统运行许可、硬件急停、软件急停、仿真急停、设备保护、全局急停锁存、复位流程和安全事件记录。安全设计遵循 fail-safe 原则：任何安全输入不可读、状态不确定、通信中断或校验失败时，运动许可趋向 0。

一期全部移除 IOC，SafetyService 在 Backend 内统一实现软件状态、仿真输入和设备访问适配；后续如果接入 EPICS，EPICS 只作为 Access 层的接口实现，不改变安全状态模型。真实硬件急停必须由独立硬件回路保证，软件不能替代物理安全回路。

## 17.2 设计目标

1. 支持 SIM、HW、SW 三类急停源。
2. 支持控制台、机柜、现场等多个硬件急停输入。
3. 任一急停源触发即可撤销全局运动许可。
4. 全局急停具有自保持锁存，不能因输入短暂恢复自动解除。
5. 软急停可以由授权用户或系统策略触发。
6. 硬件急停优先于软件和业务命令。
7. Permit 链路不可读或状态未知时按不许可处理。
8. 安全停止不依赖数据库、普通任务队列或前端在线。
9. 单设备故障可以限制设备或资源组，不无故影响无关设备。
10. 复位有清晰的物理、逻辑、授权和状态确认条件。
11. 所有安全动作可审计、可追踪、可回放。
12. 真实、仿真、混合模式在安全语义上保持一致。

## 17.3 安全分层

~~~mermaid
flowchart TB
    HW[独立硬件安全回路]
    INPUT[SIM/HW/SW inputs]
    SAFETY[SafetyService]
    PERMIT[Global and device Permit]
    CTRL[Controller stop path]
    ACCESS[Access adapter]
    DEVICE[Device protection]
    AUDIT[Audit and alarm]

    HW --> INPUT
    INPUT --> SAFETY
    SAFETY --> PERMIT
    PERMIT --> CTRL
    CTRL --> ACCESS
    ACCESS --> DEVICE
    SAFETY --> AUDIT
~~~

硬件回路可以直接断开执行器能量或使设备进入安全状态；Backend 负责读取、显示、记录和协同停止，不能把软件状态当作物理安全回路的替代品。

## 17.4 三源急停

### 17.4.1 SIM_ESTOP

仿真急停用于测试和演示。它必须模拟真实急停的锁存、传播、停止和复位语义，不能因为是仿真就绕过权限和审计。

### 17.4.2 HW_ESTOP

硬件急停来源至少包括：

~~~text
HW_CONSOLE
HW_CABINET
HW_FIELD
HW_EXTERNAL
~~~

输入可以由 GPIO、数字量模块、设备 Access、串行安全控制器或后续 EPICS 映射提供。任何输入断线、超时、非法值或质量不良默认视为触发或不可许可。

### 17.4.3 SW_ESTOP

软件急停来源包括用户请求、自动安全策略、看门狗、通信失联、设备故障和系统关闭。软件急停必须记录触发主体、原因、来源和范围。

## 17.5 安全状态

~~~text
SAFE_INIT
SAFE
PERMITTED
STOP_REQUESTED
STOPPING
ESTOP_ACTIVE
ESTOP_LATCHED
RESET_PENDING
RESETTING
FAULT
UNKNOWN
~~~

定义：

- SAFE：已停止且没有急停触发，但尚未允许运动；
- PERMITTED：全部许可条件满足；
- ESTOP_ACTIVE：至少一个急停输入处于活动；
- ESTOP_LATCHED：急停触发事实已锁存；
- UNKNOWN：无法确认输入或设备安全状态；
- RESET_PENDING：输入恢复，等待复位；
- RESETTING：正在执行复位检查。

## 17.6 安全状态机

~~~mermaid
stateDiagram-v2
    [*] --> SAFE_INIT
    SAFE_INIT --> SAFE: inputs valid and devices stopped
    SAFE --> PERMITTED: mode and permit checks pass
    PERMITTED --> STOP_REQUESTED: stop command
    PERMITTED --> ESTOP_ACTIVE: any estop source active
    SAFE --> ESTOP_ACTIVE: any estop source active
    ESTOP_ACTIVE --> ESTOP_LATCHED: latch event
    ESTOP_LATCHED --> RESET_PENDING: all inputs released
    RESET_PENDING --> RESETTING: authorized reset request
    RESETTING --> SAFE: checks pass
    RESETTING --> ESTOP_LATCHED: input active or check fails
    SAFE --> UNKNOWN: input unavailable
    UNKNOWN --> ESTOP_LATCHED: fail-safe latch
~~~

系统不得从 ESTOP_LATCHED 直接进入 PERMITTED。

## 17.7 输入聚合

~~~text
global_estop =
    SIM_ESTOP
    OR HW_CONSOLE
    OR HW_CABINET
    OR HW_FIELD
    OR HW_EXTERNAL
    OR SW_ESTOP
    OR WATCHDOG_ESTOP
~~~

对于每个输入保存：

~~~text
SafetyInput {
    input_id
    source
    active
    quality
    last_update
    timeout
    raw_value
    normalized_value
    reason
}
~~~

raw_value 只供诊断和受限权限查看；业务只使用 normalized_value 和 quality。

## 17.8 Permit 模型

全局运动许可：

~~~text
global_permit =
    process_ready
    && config_valid
    && safety_inputs_valid
    && !global_estop
    && !global_latched
    && system_mode_allowed
    && hardware_permit
~~~

设备许可：

~~~text
device_permit =
    global_permit
    && device_connected
    && device_state_ready
    && !device_fault
    && owner_valid
    && resource_valid
    && device_mode_allowed
    && capability_valid
~~~

Permit 是只读派生状态，客户端不能直接写入。任何组成条件变成 UNKNOWN 时，Permit=0。

## 17.9 设备级故障与全局急停

以下故障默认只影响设备：

- 单个相机连接失败；
- GAM1 采样失败；
- R1 驱动故障且未涉及共享安全组；
- 单个设备状态不一致。

以下情况可以影响资源组或全局：

- 双臂共享工作空间安全状态未知；
- 硬件急停；
- 安全控制器通信失联；
- 全局看门狗超时；
- 无法确认运动设备是否停止；
- 安全配置校验失败。

影响范围由 SafetyPolicy 配置，但硬件急停和安全输入不确定必须按全局 fail-safe 处理。

## 17.10 急停触发流程

~~~mermaid
sequenceDiagram
    participant I as Safety Input
    participant S as SafetyService
    participant C as Controller
    participant A as Access
    participant D as Device
    participant DB as Audit/db

    I->>S: active or invalid input
    S->>S: latch global state
    S->>C: emergency stop broadcast
    C->>A: independent STOP
    A->>D: device stop
    S->>DB: record trigger
    D-->>C: stopped or timeout
    C-->>S: device result
    S->>DB: record final safety result
~~~

触发路径必须避免等待普通数据库事务。审计写入失败时先进入内存/本地安全缓冲，恢复后补写。

## 17.11 停止层级

| 层级 | 行为 |
| --- | --- |
| SOFT_CANCEL | 取消尚未开始的业务命令 |
| CONTROL_STOP | Controller 受控停止 |
| DEVICE_STOP | Access 调用设备停止接口 |
| SAFETY_STOP | 安全通道广播停止 |
| HARDWARE_CUTOFF | 独立硬件回路断能或安全保持 |

普通 STOP 不一定等同于硬件断能；实际等级由设备能力和安全评审确定。接口结果必须明确实际执行层级。

## 17.12 硬件急停协作

硬件急停触发时：

1. 硬件回路优先让设备进入安全状态；
2. Backend 读取 HW 状态并锁存；
3. Controller 向可通信设备发送补充 STOP；
4. 所有普通 OWNER 和任务许可撤销；
5. 运行任务进入 SAFETY_STOPPED 或 UNKNOWN；
6. 相机拍照、GAM1 采样等非运动动作按策略处理；
7. 系统状态进入 ESTOP_LATCHED；
8. 只有完成物理释放和软件复位才可能恢复。

软件不能伪造 HW_RELEASED。

## 17.13 软急停协作

软件急停由用户、看门狗、设备故障策略或关闭流程触发。软件急停至少包括：

~~~text
source
scope
reason
actor
triggered_at
latch
reset_policy
operation_id
~~~

用户触发的 SW_ESTOP 默认全局锁存，除非明确配置为设备级停止。系统检测到 WebSocket 断线时，不应简单假定用户要求全局急停，而是按当前控制租约和 JOG 策略执行受控停止。

## 17.14 仿真急停

仿真界面提供：

~~~text
POST /api/safety/sim-estop/trigger
POST /api/safety/sim-estop/release
~~~

release 仅释放模拟输入，不清除全局锁存。必须继续调用 reset 流程。仿真测试应覆盖：

- 运动中触发；
- 等待资源时触发；
- 相机动作中触发；
- GAM1 采样中触发；
- 输入恢复但不复位；
- 复位权限不足；
- 设备停止超时。

## 17.15 复位流程

复位不等于 release。推荐顺序：

1. 确认所有急停输入物理释放；
2. 确认 HW 输入质量良好；
3. 确认设备停止或处于安全状态；
4. 确认无运动命令残留；
5. 确认共享工作空间无人/无冲突；
6. 具有 safety:reset 权限的用户发起请求；
7. SafetyService 进入 RESETTING；
8. 重新计算 Permit；
9. 清除全局锁存；
10. 进入 SAFE_INIT/SAFE；
11. 由用户或策略重新选择 MANUAL/AUTO；
12. 重新申请 OWNER 和资源；
13. 自动任务默认不续跑。

任一步失败都回到 ESTOP_LATCHED 或 UNKNOWN。

## 17.16 复位审计

记录：

~~~text
reset_request_id
actor_id
source_state
input_snapshot
device_snapshot
permission_result
reset_checks
result
failure_reason
trace_id
~~~

安全复位必须能回答：谁在什么时间、基于哪些输入、对哪些设备执行了什么复位。

## 17.17 看门狗

看门狗监控：

- SafetyService 主循环；
- Controller 心跳；
- Communication 线程；
- 设备状态更新时间；
- 关键事件处理延迟；
- 硬件安全输入更新时间；
- 进程锁和内存异常。

看门狗超时触发 SW_ESTOP 或将 Permit 置 0。看门狗自身故障必须 fail-safe，不能因为监控线程停止而留下 Permit=1。

## 17.18 EPICS 自保护兼容

一期不启动 IOC，但为未来 Access/EPICS 适配保留以下语义：

- Safety Permit PV 只能由安全逻辑产生；
- 设备侧保护继续在 Device/Access 内执行；
- Safety Access 不可达时，设备 Access 将 Permit 视为 0；
- raw/internal PV 一期不向普通 API 暴露；
- 读写分离不改变写命令的安全前置条件；
- EPICS 状态与 Backend 状态必须通过质量、时间戳和版本关联；
- EPICS 重连后不能自动恢复运动命令。

## 17.19 安全事件和告警

安全事件至少包括：

~~~text
ESTOP_TRIGGERED
ESTOP_LATCHED
ESTOP_INPUT_INVALID
PERMIT_LOST
PERMIT_RESTORED
DEVICE_STOP_TIMEOUT
RESET_REQUESTED
RESET_REJECTED
RESET_SUCCEEDED
WATCHDOG_TIMEOUT
SAFETY_COMMUNICATION_LOST
~~~

事件进入 AlarmService 和 AuditService。PERMIT 短时抖动要有去抖和恢复策略，但急停输入不能以普通去抖延迟危险停止。

## 17.20 安全接口

~~~text
GET  /api/safety/state
GET  /api/safety/inputs
GET  /api/safety/permit
POST /api/safety/stop
POST /api/safety/sim-estop/trigger
POST /api/safety/reset
GET  /api/safety/history
~~~

安全查询按照权限返回原始输入详情；普通用户只看归一化状态和操作结果。

## 17.21 异常策略

| 异常 | 安全结果 |
| --- | --- |
| 输入超时 | Permit=0，必要时锁存 |
| 安全状态解析失败 | Permit=0 |
| Controller 无响应 | 独立停止通道，记录超时 |
| Access 连接断开 | 禁止运动，按策略触发 SW_ESTOP |
| 数据库不可用 | 安全动作继续，审计缓冲 |
| WebSocket 断开 | 按控制租约策略停止，不直接伪造急停 |
| 设备停止未知 | 状态 UNKNOWN，禁止复位 |
| 配置缺失 | 拒绝启动或进入 SAFE_INIT |
| 前端权限不足 | 拒绝复位，不改变安全状态 |

## 17.22 测试设计

1. 三源急停各自触发和同时触发；
2. 控制台、机柜、现场硬件输入；
3. 输入断线、超时、非法值和恢复；
4. 运动中、任务等待中、拍照中、采样中触发；
5. Permit 链路任一条件为 0/UNKNOWN；
6. 全局锁存和错误复位；
7. 物理释放后复位检查；
8. R1 故障对 R2 的隔离；
9. 双臂共享工作空间故障；
10. 看门狗超时；
11. 数据库、通信和事件总线故障；
12. 仿真与真实适配器等价性；
13. 未来 EPICS Access 不可达时的 fail-safe；
14. 审计、告警和状态页面一致性。

## 17.23 验收追踪

- SIM/HW/SW 三源急停均可触发全局停止；
- 急停具有自保持锁存；
- 输入不确定时 Permit=0；
- STOP/急停不依赖普通业务队列和数据库；
- 复位必须经过释放、停止、授权和检查；
- 管理员不能绕过硬件急停；
- 单设备故障按范围隔离；
- 设备停止未知时不能复位或自动续跑；
- 安全状态、告警、审计和历史可追溯；
- 一期无 IOC 仍能完成仿真安全闭环。

## 17.24 本章小结

本章完成了 MRSS 安全与急停设计，统一定义了 SIM/HW/SW 三源急停、全局锁存、Permit 链、设备级隔离、Controller/Access 停止路径、复位流程、看门狗、EPICS 自保护兼容和安全审计。安全逻辑以 fail-safe 为核心，任何未知状态都不能产生运动许可。
