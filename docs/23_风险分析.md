# 第23章 风险分析

## 23.1 概述

本章识别 MRSS 一期在安全、设备、软件、通信、数据、部署、项目和运维方面的风险，定义风险等级、预防措施、监控信号、应急处置和残余风险。风险分析不替代现场安全评审和法规要求；涉及人身安全的硬件回路必须由具备资质的人员确认。

## 23.2 评估方法

风险等级由概率 P 和影响 I 共同确定：

~~~text
risk_score = probability * impact
~~~

等级：

| 分值 | 等级 | 处理 |
| --- | --- | --- |
| 1-4 | 低 | 常规控制 |
| 5-9 | 中 | 制定缓解措施并跟踪 |
| 10-16 | 高 | 负责人批准后实施 |
| 17-25 | 极高 | 未关闭前不得进入相关运行阶段 |

P 和 I 使用 1～5 级，评估时保留理由和证据。

## 23.5 安全风险

### 23.5.1 急停输入失效

风险：硬件输入线断、设备不可达或解析错误时系统错误地保持允许运动。

措施：

- 输入质量和更新时间检查；
- 不可读按触发/不许可；
- 独立硬件回路；
- SIM/HW/SW 测试；
- Permit 派生且不可写；
- 现场定期测试；
- 复位必须人工确认。

残余风险：现场硬件回路、接线和操作条件仍需由安全负责人验证。

### 23.5.2 停止结果未知

风险：网络超时后设备可能已动作，系统重复下发或错误复位。

措施：

- operation 状态 UNKNOWN；
- 查询设备状态和命令结果；
- 禁止自动盲目重试；
- 禁止未知时复位；
- 记录 STOP 和人工确认；
- 真实设备能力评审。

## 23.6 设备风险

### 厂商 SDK 崩溃或阻塞

Access 进程内隔离、超时、看门狗、独立执行器和适配器重启策略。无法隔离时限制调用线程并保护 STOP 通道。

### 设备状态与 Backend 不一致

使用版本、时间、质量、快照和定期对账。状态未知时禁止运动，不把最后一次 GOOD 当成当前安全状态。

### 单设备故障扩散

设备实例独立队列、连接、状态和资源。协同任务可以按策略整体失败，但无关设备保持可用。

## 23.7 软件风险

### 状态机跳转错误

采用白名单转换、状态表测试、事件幂等和重启恢复。关键状态变化写入历史，禁止任意字符串赋值。

### 线程死锁或饥饿

模块化执行器、有界队列、锁顺序规则、超时、静态分析、TSAN 和压力测试。控制线程不等待数据库长事务。

### 结果被错误标记成功

ServiceResult 明确 ACCEPTED、SUCCEEDED、FAILED、UNKNOWN；数据库提交未知时不伪造成功；前端根据状态展示。

### 配置改变运行安全

安全配置版本化、白名单、范围检查、审批、审计和热更新前置验证。失败时继续使用上一个有效版本或进入 SAFE_INIT。

## 23.8 通信风险

| 风险 | 预防 | 处置 |
| --- | --- | --- |
| TCP 断线 | 心跳、超时 | 标记 OFFLINE，有限重连 |
| UDP 丢包 | 序列、超时、质量 | 丢弃旧包并告警 |
| WebSocket 断开 | 心跳、last_seq | 重连和 RESYNC |
| 网络延迟 | deadline | 结果 UNKNOWN |
| 端口冲突 | 启动校验 | 拒绝启动并提示 |
| TLS 证书过期 | 到期监控 | readiness 失败 |
| 消息重复 | event_id | 幂等去重 |

## 23.9 数据风险

### 数据库损坏或磁盘满

措施：

- PostgreSQL 备份和 WAL；
- 磁盘空间告警；
- 历史与媒体分区；
- 高价值事件优先；
- 恢复演练；
- 数据一致性检查；
- 安全路径不依赖数据库提交。

### 数据误删

使用权限、软删除/归档、备份、审计和恢复演练。不可逆清理必须有范围、策略和审批。

### 单位或时间错误

数据模型强制 unit、quality、measured_at、received_at 和 source。配置加载验证同一 metric 的单位，查询显示单位，不在页面隐式换算。

## 23.10 安全和权限风险

- 默认拒绝未知权限；
- Token 短时效、轮换和撤销；
- 密码哈希；
- 账号锁定；
- TLS；
- 设备范围权限；
- 控制、复位、配置和导出分别授权；
- 审计权限拒绝和管理员变更；
- 定期更换设备凭据。

权限通过不等于 Permit，通过 auth 后仍要经过模式、OWNER、资源和安全检查。

## 23.11 部署风险

### 以 root 运行

使用 mrss 专用用户、目录权限、systemd NoNewPrivileges 和最小设备组权限。

### 配置和代码版本不匹配

启动时检查应用版本、配置 schema、数据库迁移和设备配置版本，不匹配则拒绝或维护启动。

### 升级后自动危险运行

启动默认 SAFE_INIT；未完成任务标记 UNKNOWN/RECOVERY_PENDING；不会自动恢复运动。

## 23.12 运维风险

| 风险 | 控制 |
| --- | --- |
| 操作人员误触控制 | 权限、确认、操作反馈、审计 |
| 忘记释放 OWNER | TTL、心跳、过期告警 |
| 告警未确认 | 页面状态、提醒、升级 |
| 备份从未恢复 | 定期恢复演练 |
| 日志没有查看 | 运维命令、报表和检查项 |
| 现场设备变更未同步 | 设备配置版本和变更审批 |
| 安全复位不规范 | 复位清单和培训 |

## 23.13 进度和资源风险

### 真实设备延期

用仿真适配器先完成 API、调度、告警、审计和安全闭环；真实设备到位后只验证 Access 和时序差异。

### 多模块并行导致接口漂移

以接口和状态模型为基线，变更需要影响分析；每个迭代执行集成测试。

### 人员不足

优先交付安全、控制、数据一致性和基本设备闭环；延后非关键报表和高级分析，但不能削弱急停和审计。

## 23.14 IOC 边界风险

一期明确：

- 全部移除 IOC；
- Backend 直接承担一期协同、安全和状态管理；
- EPICS 只保留 Access 兼容设计；
- 不以 PV Service 代替业务状态机；
- 不同时维护两套事实来源。

未来接入 EPICS 时，先定义单一事实源、同步方向、断线 fail-safe 和迁移测试，不直接把 IOC 加到生产链路。

## 23.16 应急处置流程

通用流程：

1. 发现和确认；
2. 保护人员和设备；
3. 触发 STOP/急停；
4. 保留日志、审计和状态；
5. 隔离故障设备或网络；
6. 评估影响范围；
7. 恢复数据库/通信/设备；
8. 从 SAFE_INIT 重新启动；
9. 验证状态和 Permit；
10. 形成事故记录和改进项。

## 23.17 风险接受

任何残余风险需要：

- 风险描述；
- 已有措施；
- 测试证据；
- 责任人；
- 接受期限；
- 适用环境；
- 重新评估条件。

高风险和极高风险不能由开发人员单独接受。

## 23.18 测试与风险关联

每个高风险至少关联：

~~~text
risk_id
requirement_id
test_case_id
test_result
evidence
owner
retest_condition
~~~

风险关闭必须有测试、评审或现场证据。单纯修改状态为“已解决”不构成关闭。

## 23.19 本章小结

本章完成了 MRSS 一期安全、设备、软件、通信、数据、权限、部署、运维、进度和 IOC 边界风险分析，建立了风险登记、等级、缓解、监控、应急、接受和测试关联机制。核心原则是：未知状态不产生运动许可，故障按范围隔离，安全路径独立，仿真保证进度，现场安全评审保证最终运行条件。
