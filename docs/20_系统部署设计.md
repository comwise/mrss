# 第20章 系统部署设计

## 20.1 概述

本章定义 MRSS 一期 Backend、PostgreSQL、配置、设备适配器、日志、媒体、systemd 服务和运维工具的部署方式。部署目标是让仿真、真实和混合设备可以通过同一套程序和 API 运行，切换设备类型不改变上层业务和数据库模型。

一期不部署 IOC。未来 EPICS/IOC 接入属于 Access 扩展，不能成为一期 Backend 启动的硬依赖。

## 20.2 部署目标

1. 提供可重复安装、升级、回滚和卸载流程。
2. 明确应用、数据库、配置、日志、图片和临时目录。
3. 使用最小权限运行 Backend 和 PostgreSQL。
4. systemd 负责进程拉起和重启，应用负责安全生命周期。
5. 仿真、真实和混合模式由配置选择。
6. 数据库、日志和媒体可独立备份恢复。
7. 部署失败不留下半启用服务或错误权限。
8. 端口、TLS、凭据和设备网络边界可审计。
9. 提供健康检查、版本查询和诊断命令。
10. 支持单机一期和后续拆分部署。

## 20.3 部署拓扑

~~~mermaid
flowchart TB
    USER[Web browser or Phoebus client]
    NGINX[Nginx or reverse proxy]
    BACKEND[MRSS Backend]
    PG[PostgreSQL]
    MEDIA[Media storage]
    DEV[Real or simulated devices]

    USER --> NGINX
    NGINX --> BACKEND
    BACKEND --> PG
    BACKEND --> MEDIA
    BACKEND --> DEV
~~~

一期单机模式下 Nginx、Backend、PostgreSQL 和仿真设备可以位于同一主机；真实设备通过隔离网络连接。

## 20.4 主机要求

最低要求由现场规模和设备数量确定，至少评估：

| 项目 | 要求 |
| --- | --- |
| OS | 受支持的 Ubuntu LTS 或等价 Linux |
| CPU | 满足 Backend、PostgreSQL、仿真和监控并发 |
| 内存 | 满足数据库缓存、任务队列和图片索引 |
| 磁盘 | 系统、数据库、日志、图片分区分开评估 |
| 网络 | 管理网、设备网、数据库访问边界明确 |
| 时间 | NTP/Chrony 同步，记录时钟质量 |
| 权限 | 独立 mrss 用户和 postgres 用户 |
| 备份 | 至少有独立备份目标 |
| 安全 | 防火墙、TLS、最小服务和补丁策略 |

生产容量以压测结果为准，不能只按开发机配置估算。

## 20.5 目录布局

示例布局：

~~~text
/opt/mrss/

  lib/
  share/
  migrations/
  scripts/

/etc/mrss/
  config.yaml
  devices.yaml
  tls/
  secrets/

/var/lib/mrss/
  runtime/
  media/
  export/
  backup-staging/

/var/log/mrss/
  backend/
  audit/

/run/mrss/

  control.sock
~~~

PostgreSQL 数据目录由 PostgreSQL 服务和部署环境管理，不由 SOCI 或 Backend 直接创建。

## 20.6 运行用户与权限

建议：

~~~text
用户：mrss
组：mrss
配置：root:mrss，目录 0750
密钥：root:mrss，文件 0640 或更严格
日志：mrss:mrss
媒体：mrss:mrss
数据库：postgres:postgres
~~~

Backend 不使用 root 运行。设备访问如需 GPIO、串口或输入设备权限，使用最小化 udev 规则和专用组，不把 mrss 加入无关特权组。

## 20.7 软件包

安装包至少包含：

- Backend 可执行文件；
- 共享库和第三方运行库；
- 默认配置模板；
- 数据库迁移；
- systemd 单元；
- 健康检查和诊断脚本；
- 版本和变更说明；
- 许可证和依赖清单；
- 仿真设备配置；
- 回滚所需的旧版本信息。

构建阶段固定 C++ 标准、编译器、依赖版本和构建选项。生产包不携带调试私钥和测试凭据。

## 20.8 配置文件

主配置分层：

~~~yaml
application:
  name: mrss_backend
  profile: simulation
server:
  http:
    listen: 0.0.0.0
    port: 8888
  websocket:
    port: 8900
database:
  driver: postgresql
  host: 127.0.0.1
  port: 5433
devices:
  mode: mixed
safety:
  initial_state: SAFE_INIT
logging:
  directory: /var/log/mrss/backend
media:
  root: /var/lib/mrss/media
~~~

示例不包含密码和真实设备凭据。实际端口、地址和模式必须由现场配置决定。

## 20.10 PostgreSQL 部署

部署步骤：

1. 安装受支持的 PostgreSQL 版本；
2. 创建数据库和最小权限用户；
3. 配置监听地址、认证和端口；
4. 创建 schema；
5. 执行迁移；
6. 建立备份和 WAL 策略；
7. 验证连接池和时区；
8. 设置磁盘、日志和权限；
9. 执行恢复演练。

数据库连接串不写入命令行历史和普通日志。Backend 通过 db 配置或受控环境引用访问数据库。

## 20.11 systemd 服务

示例：

~~~ini
[Unit]
Description=MRSS Backend
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=mrss
Group=mrss
ExecStart=/opt/mrss/bin/mrss_backend --config /etc/mrss/config.yaml
Restart=on-failure
RestartSec=3
TimeoutStopSec=60
LimitNOFILE=65536
NoNewPrivileges=true
PrivateTmp=true
WorkingDirectory=/opt/mrss

[Install]
WantedBy=multi-user.target
~~~

服务启动后必须通过 readiness 检查，而不是仅依据 systemd active 状态判断可用。

## 20.12 Nginx 和同源访问

Nginx 可将 Web、HTTP API 和 WebSocket 反代为同源地址：

~~~text
/            -> frontend static files
/api/        -> Backend HTTP
/ws          -> Backend WebSocket
/media/      -> authorized media proxy
~~~

媒体不能通过直接 alias 暴露整个目录。Nginx 的 WebSocket Upgrade、超时、请求大小、TLS 和访问日志按安全配置处理。

## 20.13 网络和端口

端口必须配置化并形成现场清单：

| 服务 | 方向 | 说明 |
| --- | --- | --- |
| HTTP | 客户端 -> Backend/Nginx | API 和健康 |
| WebSocket | 客户端 -> Backend/Nginx | 实时事件 |
| TCP/UDP | Backend -> 设备 | 厂商或 Access 协议 |
| PostgreSQL | Backend -> DB | 仅内部 |
| 管理 | 运维 -> 主机 | SSH 或受控工具 |

一期不依赖 IOC 端口。未来增加 EPICS/Access 端口时必须更新防火墙和安全评审。

## 20.14 TLS 和凭据

生产环境：

1. API 和 WebSocket 使用 TLS；
2. 证书由受控目录读取；
3. 私钥只有 mrss 进程可读；
4. 证书轮换不打印私钥；
5. 设备凭据按适配器隔离；
6. 凭据变更产生审计；
7. 配置备份不包含明文秘密；
8. 失效证书导致 readiness 失败，不静默降级为明文。

## 20.15 安装流程

~~~text
校验系统和用户
  -> 安装文件
  -> 创建目录和权限
  -> 校验配置
  -> 初始化数据库/迁移
  -> 安装 systemd
  -> 启动 Backend
  -> 检查 health/readiness
  -> 检查五类设备注册
  -> 输出版本和诊断结果
~~~

安装失败时服务保持 disabled 或 stopped，避免半配置服务被系统自动拉起。

## 20.16 升级流程

1. 查看当前版本和数据库版本；
2. 备份数据库、配置、媒体索引和迁移状态；
3. 停止新任务；
4. 进入维护模式；
5. 对运行设备执行安全停止；
6. 停止 Backend；
7. 安装新包；
8. 执行向前迁移；
9. 运行 schema 检查；
10. 启动 Backend；
11. 保持 SAFE_INIT；
12. 检查健康、设备和数据；
13. 经授权后恢复业务。

升级过程不自动回滚数据库到旧版本；应用回滚必须有兼容性评估。

## 20.17 回滚

应用回滚：

- 保存上一版本包；
- 停止新版本；
- 恢复应用文件；
- 使用兼容数据库 schema；
- 启动并检查；
- 进入 SAFE_INIT；
- 记录回滚审计。

数据库迁移若不可逆，使用备份恢复到新建实例后切换，不在线覆盖生产数据目录。

## 20.18 备份

备份对象：

~~~text
PostgreSQL data
WAL/incremental
/etc/mrss/config.yaml
/etc/mrss/devices.yaml
migration metadata
media metadata
media files
audit export
version manifest
~~~

备份成功、失败、校验和、保留周期和恢复测试都写入运维审计。备份文件加密并限制访问。

## 20.19 监控和运维命令

~~~text
systemctl status mrss-backend
journalctl -u mrss-backend
mrss_backend --check-config --config /etc/mrss/config.yaml
mrss_backend --print-version
curl /api/system/health
curl /api/system/readiness
~~~

诊断工具不得输出密码、Token 和设备凭据。需要特权的命令通过 sudo 白名单控制。

## 20.20 部署验证

部署完成后验证：

1. 服务用户和文件权限；
2. 配置版本和秘密引用；
3. PostgreSQL 连接和 schema；
4. HTTP、WebSocket 和健康接口；
5. 五类设备状态；
6. 仿真 MOVEJ/JOG/STOP；
7. 相机拍照；
8. GAM1 采样；
9. SIM_ESTOP 和复位；
10. 任务、告警、审计和历史；
11. 备份和恢复；
12. systemd 重启后的 SAFE_INIT。

## 20.21 测试设计

- 干净主机安装；
- 重复安装；
- 配置错误安装；
- 数据库未启动；
- 端口占用；
- 文件权限错误；
- TLS 证书过期；
- 模式切换和设备混合；
- 升级、回滚和迁移；
- 日志轮转和磁盘满；
- 备份失败和恢复；
- systemd 异常重启；
- 安全停止超时。

## 20.22 验收追踪

- 一键或脚本化安装可重复；
- Backend 不以 root 运行；
- PostgreSQL 数据目录由数据库管理；
- 一期不依赖 IOC；
- 仿真/真实/混合只通过配置切换；
- systemd、health、readiness 和诊断可用；
- 升级、回滚、备份恢复可演练；
- 凭据、TLS、日志和媒体权限符合要求。

## 20.23 本章小结

本章定义了 MRSS 一期的主机、目录、用户、软件包、配置、PostgreSQL、systemd、Nginx、TLS、设备模式、升级、回滚、备份和部署验证方案。部署以最小权限、可重复、可恢复和安全初始状态为原则，不将 IOC 作为一期运行依赖。
