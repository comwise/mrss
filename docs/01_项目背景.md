# 第1章 项目背景

## 1.1 项目概述

MRSS 是面向机器人、机械臂、工业相机及环境传感器的统一监控、控制和任务调度系统。系统通过 Web 提供操作与监控界面，通过 Backend 完成用户认证、设备管理、任务调度、协同控制、安全联锁、数据存储、告警和审计等核心能力，并通过统一设备接口连接仿真设备与真实设备。

MRSS 一期以“系统可运行、功能可验证、设备可替换”为建设原则，优先建立从用户操作、后端处理、设备执行到状态反馈和数据记录的完整闭环，为后续接入更多设备、扩展复杂任务和引入 EPICS 等平台能力提供稳定基础。

## 1.2 建设背景

项目现场包含多台异构设备，不同设备在通信协议、控制方式、状态模型和异常处理方面存在明显差异：

- 瑞尔曼机械臂主要承担点动、单点运动、连续轨迹和双臂协同等运动任务；
- 海康相机承担实时图像、云台控制、变焦、聚焦和拍照等任务；
- 辐射传感器承担环境辐射数据采集、阈值判断和异常报警；
- 仿真设备用于在真实硬件未到位或不便使用时完成接口联调、业务验证和自动化测试。

如果 Web 或业务代码直接依赖各厂商 SDK 和设备协议，会导致设备替换困难、业务逻辑与驱动逻辑耦合、仿真与真实环境行为不一致，也不利于统一处理权限、安全、任务和故障。因此，一期需要建立分层的软件架构，以统一模型管理设备，以统一流程执行任务，以统一机制处理状态、资源和安全问题。

## 1.3 现状与主要问题

### 1.3.1 设备接口不统一

不同设备采用不同的 SDK、HTTP 接口、TCP/UDP 协议或私有数据格式。上层业务若直接调用设备接口，将形成大量条件分支，难以维护和扩展。

### 1.3.2 控制与业务边界不清晰

用户请求、任务调度、设备控制、协议通信和数据存储需要明确分层。若相关职责集中在单一服务或接口处理函数中，会造成代码复杂、故障难以定位，且不利于单元测试。

### 1.3.3 多设备协同缺少统一机制

系统不仅需要控制单台设备，还需要支持双机械臂协同以及“机械臂到位后相机拍照”等跨设备流程。协同任务必须具备资源占用、顺序控制、超时、取消和异常恢复能力。

### 1.3.4 安全与资源冲突风险

手动操作、自动任务和维护操作可能同时请求同一设备。系统必须通过运行模式、OWNER 和资源锁进行仲裁，同时提供仿真急停、硬件急停和软件急停的统一处理机制，避免重复控制和危险动作。

### 1.3.5 仿真与真实环境切换成本高

一期开发和测试不能完全依赖真实设备。系统需要保证仿真、真实和混合模式使用相同的上层 API、任务流程和数据库模型，仅通过配置选择具体设备适配器。

## 1.4 一期建设目标

MRSS 一期的总体目标是完成 Web、Backend 和设备之间的可运行闭环，形成可扩展、可测试、可部署的软件基础平台。

具体目标如下：

1. 建立统一的用户登录、身份认证、角色权限和操作审计机制。
2. 建立统一的设备模型、状态模型和 DeviceAdapter 接口。
3. 支持两台瑞尔曼机械臂独立控制及协同控制。
4. 支持两类海康相机的状态获取、云台控制、变焦、聚焦和拍照。
5. 支持辐射传感器数据采集、历史存储、阈值判断和报警。
6. 支持点动、单点运动、连续轨迹和协同轨迹四类运动命令。
7. 支持 Manual、Auto 模式以及设备 OWNER、资源锁和冲突仲裁。
8. 支持仿真急停、硬件急停、软件急停及全局急停锁存和恢复。
9. 支持设备故障隔离，单台设备故障不应无条件阻断其他无关设备。
10. 支持仿真、真实和混合三种运行方式，切换后上层 API 和业务流程保持不变。
11. 建立日志、告警、任务历史、设备数据和审计记录的统一存储能力。
12. 形成可部署、可测试、可追踪和可持续扩展的工程结构。

## 1.5 一期建设范围

### 1.5.1 软件范围

一期纳入以下软件组成：

| 组成 | 主要职责 |
| --- | --- |
| Web | 用户登录、实时监控、设备操作、任务配置、告警展示、历史查询和系统设置 |
| Backend | API、业务服务、任务调度、控制逻辑、设备管理、安全联锁、认证授权、数据存储和通信管理 |
| DeviceAdapter | 为上层提供统一设备接口，隔离厂商 SDK、网络协议和仿真实现 |
| PostgreSQL | 保存用户、角色、设备、任务、记录、报警、日志和审计数据 |
| 仿真组件 | 模拟机械臂、相机和传感器的控制、状态、数据及故障行为 |

### 1.5.2 设备范围

一期设备范围如下：

| 设备类型 | 数量/种类 | 一期主要能力 |
| --- | --- | --- |
| 瑞尔曼机械臂 | 2 台 | 状态监控、点动、单点、连续轨迹、停止、复位、独立与协同控制 |
| 海康相机 | 2 类 | 状态监控、云台、变焦、聚焦、拍照及与机械臂协同 |
| 辐射传感器 | 1 类 | 数据采集、状态监控、历史记录、阈值告警 |
| 仿真设备 | 与上述设备对应 | 正常动作、状态变化、超时、离线和故障模拟 |

### 1.5.3 运行模式

一期支持以下部署和运行组合：

- 全仿真模式：所有设备均由仿真适配器提供；
- 全真实模式：所有设备均连接真实硬件；
- 混合模式：部分设备使用真实适配器，其他设备使用仿真适配器。

设备实现由配置选择。无论采用哪种模式，Web 接口、Backend 业务流程、任务模型和数据库结构均保持一致。

## 1.6 一期范围边界

为保证一期能够按计划形成完整闭环，以下内容不作为一期强制交付范围：

1. 一期不引入 IOC，原计划由 IOC 承担的状态汇聚、设备协同和安全联锁由 Backend 实现。
2. EPICS 仅保留后续接口适配和演进空间，不作为一期设备控制主链路。
3. 暂不建设复杂的跨站点、跨系统分布式调度能力。
4. 暂不实现基于人工智能的自主任务规划和高级故障预测。
5. 暂不追求覆盖所有厂商设备，仅完成一期明确设备及其统一扩展机制。
6. 硬件级安全回路由电气系统负责，软件急停和联锁不能替代硬件安全设计。

## 1.7 建设原则

### 1.7.1 分层解耦

接口处理、业务服务、控制逻辑、设备抽象、外部适配、数据访问和公共能力分别归入明确模块，禁止业务层直接依赖厂商协议细节。

### 1.7.2 接口统一

真实设备与仿真设备实现相同的抽象接口。设备替换或运行模式切换不改变上层调用方式。

### 1.7.3 安全优先

所有运动命令在执行前必须通过权限、运行模式、设备状态、资源所有权、安全状态和参数合法性检查。急停的优先级高于任务和普通控制命令。

### 1.7.4 故障隔离

设备故障应限制在相关设备和任务范围内。只有全局安全事件或明确的协同依赖失败才升级为系统级阻断。

### 1.7.5 可观测与可追溯

关键操作、状态变化、任务执行、告警产生和安全事件均应记录，并能够关联用户、设备、任务和时间信息。

### 1.7.6 渐进实施

优先完成最小可运行闭环，再逐步增加真实设备、复杂协同、性能优化和平台集成能力，降低一次性实施风险。

## 1.8 预期成果

一期完成后应形成以下成果：

- 一套可运行的 MRSS Web 与 Backend 软件；
- 一套清晰、稳定的模块化 C++ 工程结构；
- 一套统一的设备接口及仿真/真实适配机制；
- 两台机械臂、两类相机和辐射传感器的联动能力；
- 一套任务、模式、资源锁、安全急停和故障隔离机制；
- 一套基于 PostgreSQL 的业务数据、历史记录和审计存储方案；
- 一套覆盖设计、部署、测试和实施过程的完整文档；
- 为后续 EPICS 接入、设备扩展和高级调度提供可演进基础。

## 1.9 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| MRSS | 多机器人调度与控制系统 |
| Web | MRSS 浏览器端用户界面 |
| Backend | MRSS 后端服务，承担业务、控制、数据和设备管理能力 |
| DeviceAdapter | 统一设备适配接口及其具体实现 |
| Controller | Backend 内部的设备控制、任务执行和协同控制模块 |
| Communication | HTTP、WebSocket、TCP、UDP 等通信能力的统一模块 |
| OWNER | 当前设备或资源的控制所有者 |
| Manual | 手动运行模式，由授权用户直接发起控制 |
| Auto | 自动运行模式，由任务和调度逻辑发起控制 |
| IOC | EPICS Input/Output Controller；一期不纳入运行链路 |
| EPICS | Experimental Physics and Industrial Control System |

## 1.10 本章小结

本章说明了 MRSS 的建设背景、现状问题、一期目标、实施范围和边界。MRSS 一期聚焦 Web、Backend 和明确设备之间的完整联动闭环，通过统一设备接口、分层架构、资源仲裁、安全急停、故障隔离和仿真/真实兼容机制，为后续章节的需求分析和系统设计提供基础。
