# 第21章 系统测试设计

## 21.1 概述

本章定义 MRSS 一期从单元测试、组件测试、集成测试、系统测试、性能测试、安全测试、故障注入到现场验收的测试体系。测试对象是 Web/API、Backend、db、Controller、Device、Access、仿真设备、真实设备适配器、任务协同和安全急停的完整闭环。

一期以仿真为主完成软件闭环，同时保留真实设备适配器的接口和验证入口。测试不引入 IOC 作为前置条件；未来 EPICS 接入作为 Access 变体增加兼容性测试。

## 21.2 测试目标

1. 验证功能需求和设计约束全部可执行。
2. 验证五类一期设备的统一模型和状态生命周期。
3. 验证 R1/R2 独立控制和双臂协同。
4. 验证相机拍照、PTZ、GAM1 采样和历史记录。
5. 验证 Manual/Auto、OWNER、资源锁和任务调度。
6. 验证 SIM/HW/SW 急停和 Permit fail-safe。
7. 验证单设备故障隔离和结果 UNKNOWN 处理。
8. 验证 auth、RBAC、API、WebSocket 和审计。
9. 验证 PostgreSQL/SOCI、迁移、备份和恢复。
10. 验证部署、升级、回滚和 systemd 生命周期。
11. 建立可重复、可自动化和可追踪的测试证据。

### 单元测试

验证纯函数、状态机、错误映射、阈值、权限和时间策略。

### 组件测试

验证 Controller、Scheduler、SafetyService、ResourceService、db、Communication 和仿真适配器。

### 集成测试

验证多个模块与 PostgreSQL、文件系统、WebSocket 和设备仿真协作。

### 系统测试

验证从登录到任务、控制、告警、审计和历史的完整闭环。

### 验收测试

按需求编号、验收标准和现场操作步骤执行并留存结果。

## 21.4 测试环境

| 环境 | 用途 |
| --- | --- |
| Unit | 无外部依赖，Fake Clock/Fake Repository |
| Simulation | 五类仿真设备的完整闭环 |
| Mixed | 仿真设备与真实设备适配器混合 |
| Hardware-in-loop | 单个真实设备和安全输入验证 |
| Field | 现场网络、设备和部署验证 |
| Recovery | 数据库故障、备份和恢复 |

测试数据、配置和凭据必须隔离。生产数据库禁止用于自动化测试。

## 21.5 测试数据和可重复性

每轮系统测试开始前：

1. 创建独立数据库或 schema；
2. 执行固定迁移；
3. 加载最小用户、角色和设备配置；
4. 清空任务、操作、告警和审计测试数据；
5. 固定仿真时钟或记录时间；
6. 固定设备随机种子；
7. 生成 test_run_id；
8. 保存配置、版本和环境摘要。

测试结束后保留失败证据，成功数据按策略清理。

## 21.10 设备闭环测试

### R1/R2 独立 MOVEJ

1. 登录并获取控制权限；
2. 申请对应 OWNER；
3. 校验 MODE、RESOURCE、PERMIT；
4. 提交 MOVEJ；
5. 观察 RUNNING/MOVING_POINT；
6. 仿真或真实设备更新关节状态；
7. 产生 ARRIVED；
8. 写入 operation、device history 和 audit；
9. 释放或续期资源。

分别对 R1 和 R2执行，并验证一方故障不影响另一方。

### JOG

验证开始、持续、心跳、超时、断线和停止。JOG 不能在租约过期后继续输出。

### STOP

验证普通队列有阻塞时仍能执行，重复 STOP 幂等，停止结果确认和超时记录。

### 相机

固定相机验证 SNAPSHOT、IMAGE_ID、IMAGE_PATH/URI 和媒体元数据；PTZ 相机验证 PAN、TILT、ZOOM、PRESET 与拍照关联。

### GAM1

验证 SAMPLE、value、unit、quality、timestamp、历史和阈值告警。

## 21.11 协同任务测试

1. 双臂同时申请资源；
2. 双臂分别到位后 barrier 放行；
3. R1 到位、R2 超时；
4. R2 故障后停止 R1；

9. 协同任务取消和急停；
10. 任务恢复时不自动危险续跑。

## 21.14 安全测试

测试输入：

~~~text
SIM_ESTOP
HW_CONSOLE
HW_CABINET
HW_FIELD
SW_ESTOP
WATCHDOG_TIMEOUT
SAFETY_INPUT_INVALID
PERMIT_LOST
~~~

每种输入验证：

1. 是否触发停止；
2. 是否锁存；
3. Permit 是否变为 0；
4. 任务和 operation 状态；
5. 资源和 OWNER；
6. 告警和审计；
7. 输入释放是否仍保持锁存；
8. reset 权限和检查；
9. 设备停止未知时是否拒绝复位；
10. 复位后是否回到 SAFE_INIT/SAFE 而非直接 RUNNING。

## 21.15 故障注入矩阵

| 注入 | 预期 |
| --- | --- |
| PostgreSQL 停止 | 新写入降级，安全停止可用 |
| 连接池耗尽 | 有界等待，不死锁 |
| HTTP 断开 | 控制租约和 JOG 安全处理 |
| WebSocket 断开 | 事件重连和状态重同步 |
| 设备 TCP 超时 | 设备 OFFLINE/FAULT，重连 |
| 设备返回非法值 | 拒绝并告警 |
| 相机拍照超时 | operation UNKNOWN 或 FAILED |
| GAM1 质量 BAD | 采样质量和告警 |
| Controller 线程阻塞 | 独立 STOP 通道 |
| Scheduler 线程异常 | 停止新任务，安全路径可用 |
| 磁盘满 | 普通写入降级，关键事件保留 |
| 配置热更新错误 | 拒绝版本，不改变旧配置 |
| 进程 SIGTERM | 安全停止和审计刷写 |
| 进程强制退出 | 重启后 SAFE_INIT 和 UNKNOWN |


安全、数据丢失、错误运动和权限绕过属于高优先级缺陷，未关闭前不得进入验收。

## 21.22 测试退出准则

满足以下条件才可以结束一期测试：

1. 需求追踪矩阵覆盖；
2. 核心功能通过；
3. 三源急停测试通过；
4. 双臂独立和协同通过；
5. 单设备故障隔离通过；
6. 数据库、备份和恢复通过；
7. 安全测试无未评估高危项；
8. 性能达到批准基线；
9. 部署升级回滚通过；
10. 关键缺陷关闭或有书面接受；
11. 测试报告和验收记录归档。

## 21.23 本章小结

本章建立了 MRSS 一期完整测试体系，覆盖功能、状态机、设备闭环、调度、模式资源、安全急停、数据库、性能、安全、部署、故障注入和验收场景。测试以仿真闭环为基础，以真实设备和现场环境进行适配验证，所有结论必须有可追踪证据。
