# 第22章 项目实施计划

## 22.1 概述

本章给出 MRSS 一期从设计冻结、基础框架、仿真闭环、核心业务、真实设备适配、测试验收、部署交付到培训运维的实施计划。计划以“先完成可验证的软件闭环，再逐步替换真实适配器”为原则，确保硬件不齐全时仍能持续开发和测试。

一期范围固定为：

- R1、R2 两个瑞尔曼机械臂；
- HIK_FIX1 固定相机；
- HIK_PTZ1 云台相机；
- GAM1 辐射传感器；
- Web + Backend + Device/Access；
- 仿真、真实和混合运行；
- Manual/Auto、任务调度、资源仲裁、三源急停、告警、审计和历史；
- 一期不引入 IOC。

## 22.2 实施原则

1. 需求、设计、代码、测试和验收保持可追踪。
2. 先定义接口和状态模型，再实现适配器。
3. 先仿真闭环，再连接真实设备。
4. 先完成安全停止，再开放运动功能。
5. 每个阶段有可运行基线和退出准则。
6. 设备故障隔离与协同逻辑同步开发。
7. 数据库迁移和备份恢复不推迟到最后。
8. 每完成一项形成文档、代码和测试证据。
9. 不因单个真实设备延期而阻塞其他模块。
10. 所有关键决策、变更和风险进入项目记录。

## 22.4 P0 基线和环境

任务：

1. 冻结一期需求和章节设计；
2. 建立 GitHub 仓库目录和分支策略；
3. 确定 C++ 标准、编译器和构建方式；
4. 确定 PostgreSQL、SOCI、uWebSockets、yaml-cpp、jwt-cpp 等依赖；
5. 建立 CI、静态检查和单元测试框架；
6. 建立仿真、测试和现场配置模板；
7. 定义日志、trace_id、operation_id 和版本规则；
8. 建立需求追踪矩阵。

退出条件：

- 空项目可以构建；
- CI 可执行；
- 配置检查命令可用；
- 测试报告可生成；
- 仓库和分支权限明确。

## 22.5 P1 core/db/auth 基础

任务：

1. 实现 core 基础类型、Result/Error、时钟和生命周期；
2. 实现配置加载和脱敏；
3. 初始化 PostgreSQL schema；
4. 实现 SOCI 连接池、事务和 Repository；
5. 实现 User、Role、Permission 和 Session；
6. 实现密码哈希、JWT、刷新和撤销；
7. 实现登录、登出、当前用户和权限中间件；
8. 建立审计基础表和认证审计；
9. 完成数据库迁移和恢复测试。

退出条件：

- 用户可登录；
- 角色权限可判定；
- PostgreSQL 可迁移和恢复；
- 关键错误和审计可查询；
- 无明文凭据。

## 22.6 P2 Device/Access 仿真

任务：

1. 实现 Device 基类和生命周期；
2. 实现 DeviceManager、AdapterFactory；
3. 实现 SimArmAdapter；
4. 实现 SimFixedCameraAdapter；
5. 实现 SimPtzCameraAdapter；
6. 实现 SimRadiationAdapter；
7. 实现连接、状态、能力、故障和重连；
8. 实现仿真时钟和故障注入；
9. 实现统一 snapshot、command 和 event；
10. 验证全仿真配置注册五类设备。

退出条件：

- R1/R2 可以 MOVEJ/JOG/STOP；
- 固定和 PTZ 相机可以拍照；
- GAM1 可以采样；
- 设备故障和恢复可注入；
- 上层不依赖仿真类名称。

## 22.7 P3 Controller/service/api

任务：

1. 实现每设备命令队列；
2. 实现 STOP 高优先级路径；
3. 实现四类运动/控制命令模型；
4. 实现任务、设备、操作、告警基础 Service；
5. 实现 HTTP Handler 和 WebSocket 订阅；
6. 实现统一响应、错误、幂等和 trace；
7. 实现设备状态和操作结果推送；
8. 编写端到端仿真流程；
9. 建立前端联调接口文档。

退出条件：

- Web 可以登录并读取设备；
- R1/R2 独立控制闭环完成；
- 相机和 GAM1 API 可用；
- 操作结果、历史和审计可查询；
- WebSocket 可以重连和补同步。

## 22.8 P4 调度、仲裁与安全

任务：

1. 实现 Task、Point、Action 和 ExecutionPlan；
2. 实现 Manual/Auto；
3. 实现 Scheduler、优先级和定时窗口；
4. 实现 OWNER、Resource、Lease；
5. 实现双臂原子资源申请；
6. 实现双臂 barrier；
7. 实现臂到位后拍照；
8. 实现 SIM/HW/SW SafetyInput；
9. 实现 Permit、全局锁存和复位流程；
10. 实现任务取消、暂停、恢复和 UNKNOWN。

退出条件：

- 任务可以定时和手动执行；
- Manual 高于 Auto；
- 双臂协同可成功和失败；
- 任一急停会阻止运动；
- 复位不会直接恢复自动运行；
- 资源和安全审计完整。

## 22.9 P5 数据、告警和审计

任务：

1. 完善设备、任务、采样、图片、告警和审计历史；
2. 实现统一 AlarmMetricData；
3. 实现三档/五档阈值；
4. 实现百分比、容量、传感器和状态告警；
5. 实现去重、升级、确认、恢复和提醒；
6. 实现 Outbox 和 WebSocket 事件；
7. 实现历史分页、导出和归档；
8. 实现备份恢复和一致性检查；
9. 形成运行报表和测试数据。

退出条件：

- 关键运行事实可追溯；
- 告警不会无限重复；
- 安全和审计事件不丢；
- 查询、导出、备份和恢复可执行；
- 单设备数据隔离。

## 22.10 P6 真实设备与混合模式

### 22.10.1 瑞尔曼机械臂

1. 核对 SDK/通信协议和能力；
2. 实现真实适配器；
3. 映射连接、状态、关节、到位和故障；
4. 映射 MOVEJ、JOG、STOP；
5. 核对超时、重连和结果未知；
6. 低速、空载和安全区域测试；
7. 进行 R1、R2 独立及双臂协同测试。

### 22.10.2 海康固定相机

1. 核对 HTTP/SDK 能力；
2. 实现登录、抓图、超时和重连；
3. 生成受控 IMAGE_ID 和资源元数据；
4. 验证曝光、分辨率和保存策略；
5. 完成固定相机拍照闭环。

### 22.10.3 海康 PTZ 相机

1. 核对 PAN、TILT、ZOOM、PRESET；
2. 实现位置状态和动作结果；
3. 实现拍照和动作关联；
4. 验证到位、超时和断线；
5. 完成臂到位后 PTZ 调整/拍照闭环。

### 22.10.4 GAM1

1. 核对协议、单位和质量字段；
2. 实现采样、重连和超时；
3. 验证 uSv/h/CPS 等配置；
4. 验证阈值和历史；
5. 完成真实/仿真混合采样测试。

退出条件：

- 单个真实设备可替换仿真设备；
- API、任务、数据库和告警不改变；
- 混合模式可运行；
- 真实设备失败可恢复或隔离；
- 安全停止和复位测试通过。

## 22.11 P7 测试、部署和验收

任务：

1. 执行系统测试和故障注入；
2. 执行性能和安全测试；
3. 打包、安装和升级；
4. 执行备份恢复；
5. 执行现场网络和权限核对；
6. 完成操作手册和运维手册；
7. 完成培训和演示；
8. 关闭高优先级缺陷；
9. 形成验收报告；
10. 形成版本和发布清单。

退出条件：

- 测试退出准则全部满足；
- 关键安全缺陷关闭；
- 现场人员完成培训；
- 交付包和文档归档；
- 维护责任和联系方式明确。

## 22.12 迭代节奏

建议每个迭代包含：

~~~text
需求/设计确认
  -> 实现
  -> 单元测试
  -> 集成测试
  -> 演示
  -> 缺陷修复
  -> 文档更新
  -> 版本标记
~~~

每个迭代必须产出可运行版本，不把所有模块积压到最后集成。

## 22.13 角色分工

| 测试工程师 | 测试计划、自动化、故障注入 |

一个人可以承担多个角色，但安全复核和代码实现应尽量分离。

## 22.15 变更控制

变更必须说明：

~~~text
change_id
requester
reason
affected_modules
safety_impact
database_impact
compatibility
test_plan
rollback_plan
approval
~~~

涉及急停、Permit、OWNER、任务状态、数据库迁移和对外 API 的变更必须重新评审，不允许只修改代码而不更新设计和测试。

## 22.17 本章小结

本章将 MRSS 一期拆分为基线、基础、仿真、业务闭环、调度安全、数据运维、真实适配和交付八个阶段，定义了任务、退出条件、角色、交付物、变更控制和里程碑。实施路径保证软件可以先通过仿真持续验证，再渐进替换真实设备，降低硬件和现场条件对项目进度的影响。
